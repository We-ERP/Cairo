# منظومة إدارة الانتخابات — أمانة تنظيم القاهرة

نظام لإدخال أرقام اللجان، فتح/غلق الصناديق، ومتابعة الإجماليات، بواجهة ويب (GitHub Pages)
وباك اند Google Apps Script، وقاعدة بيانات Google Sheets.

## هيكل المشروع

```
backend/
  Code.gs           ← كل منطق السيرفر (Google Apps Script)
  appsscript.json   ← إعدادات مشروع Apps Script
frontend/
  index.html        ← الواجهة الكاملة (تُنشر على GitHub Pages)
README.md
```

## أهم التحديثات عن النسخة السابقة

- **تشفير كلمات المرور** (SHA-256 + Salt) بدل تخزينها نص صريح. الحسابات القديمة
  تترقّى تلقائيًا لأول مرة يسجل فيها صاحبها الدخول.
- **جلسات حقيقية (Session Tokens)**: كل طلب من الواجهة للسيرفر بيتحقق منه السيرفر
  فعليًا (مش بس إخفاء زرار في الواجهة). محدش يقدر ينادي أكشن إداري من غير تسجيل دخول.
- **صلاحيات تفصيلية لكل مستخدم**: إدخال بيانات / لوحة تحكم / إدارة مستخدمين /
  مراجعة شيتات / سجل حركات / الإجمالي النهائي — كل صلاحية تتفعّل/تتلغى individually.
- **منع تعارض الكتابة (Concurrency)**: `LockService` على كل عمليات الحفظ
  (إدخال رقم، فتح لجنة، حفظ مستخدم، تغيير باسورد) عشان لو اتنين ضغطوا في نفس اللحظة
  محصلش تكرار أو تعارض بيانات.
- **تغيير كلمة المرور الذاتي** من الواجهة (زرار المفتاح بجانب اسم المستخدم).
- **حماية شيت الصلاحيات**: كلمة المرور (المشفّرة أصلًا) بتظهر كـ `••••••••` دايمًا
  في أي عرض أو تنزيل، حتى لو حد فتح "مراجعة الشيتات".
- **شارتس حقيقية (Chart.js)** بدل الأشرطة اليدوية في لوحة تحكم الأدمن.
- إصلاح خطأ في زرار "فتح اللجنة" كان بيعلّم اللجنة إنها اتفتحت حتى لو الطلب فشل.

> ملاحظة: **كل حسابات الأرقام والماتريكس والشروط الأصلية (زي منع تكرار نفس اللجنة
> في نفس الساعة) لم تتغيّر إطلاقًا** — فقط تمت إضافة طبقة الحماية والأداء فوقها.

## 1) إعداد Google Sheet

اعمل Google Sheet فيه الشيتات دي (لو مش موجودة أصلًا عندك):

| اسم الشيت | الوصف |
|---|---|
| `Election_July` | بيانات المراكز واللجان والمندوبين |
| `Data` | الأرقام المُدخلة |
| `Codes` | حالة فتح/غلق اللجان |
| `الاجمالي` | التقارير النهائية |
| `صلاحيات المستخدمين` | حسابات المستخدمين (اسم المستخدم، كلمة المرور، القسم، الصلاحية، آخر تسجيل دخول) |
| `سجل الحركات` | يُنشأ تلقائيًا أول مرة يُسجَّل فيها أي إجراء |

أعمدة "الملح" و"الصلاحيات التفصيلية" هتتضاف تلقائيًا لشيت "صلاحيات المستخدمين"
أول ما أي أكشن يشتغل عليه (مفيش حاجة تعملها يدويًا).

**أول حساب أدمن**: أضف صف يدويًا في شيت "صلاحيات المستخدمين" باسم مستخدم وكلمة مرور
(نص صريح مبدئيًا) وقسم واختار الصلاحية `ADMIN`. أول ما يسجل دخول، النظام هيشفّر
كلمة المرور تلقائيًا ويديله كل الصلاحيات (لأنه ADMIN).

## 2) نشر الباك اند (Google Apps Script)

1. من نفس الـ Google Sheet: **الإضافات (Extensions) → Apps Script**.
2. امسح أي كود موجود، وانسخ محتوى `backend/Code.gs` بالكامل.
3. افتح `appsscript.json` من قائمة الملفات (فعّل "إظهار ملف appsscript.json" من
   إعدادات المشروع ⚙️)، واستبدل محتواه بمحتوى `backend/appsscript.json`.
4. **مهم جدًا**: في أول سطر بالكود (`CONFIG.SESSION_SECRET`)، غيّر القيمة لأي نص
   عشوائي طويل وسري خاص بيك (مفتاح توقيع الجلسات). لو سرّبته لازم تغيّره تاني.
5. **نشر (Deploy) → New deployment**:
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. انسخ رابط الـ Web App اللي هيظهر (بيخلص بـ `/exec`).
7. أي تعديل جديد في الكود لازم تعمل له **Deploy → Manage deployments → Edit → New version**
   عشان يتفعّل على الرابط الحالي.

## 3) ربط الواجهة الأمامية

في `frontend/index.html`، دوّر على السطر:

```js
const API_URL = "https://script.google.com/macros/s/.../exec";
```

واستبدله برابط الـ Web App اللي نسخته في الخطوة السابقة.

## 4) نشر الواجهة على GitHub Pages

1. ارفع المجلد ده كامل كـ Repository جديد على GitHub.
2. من إعدادات الـ Repository: **Settings → Pages**.
3. اختار Source: **Deploy from a branch**، والبرانش `main`، والمجلد `/frontend`
   (أو انقل `index.html` لجذر الريبو لو حابب تبسّط الإعداد).
4. بعد كام دقيقة هيظهر لينك عام (مثلاً `https://username.github.io/repo-name/`).

## 5) الصلاحيات التفصيلية — إزاي تستخدمها

من تبويب "صلاحيات المستخدمين" (يظهر للأدمن فقط):
- اكتب اسم المستخدم/كلمة المرور (سيبها فاضية عند التعديل لو مش عايز تغيّرها)/القسم.
- اختار "نوع الحساب" كقالب سريع (بيحدد الصلاحيات الافتراضية)، وبعدين عدّل
  الصلاحيات التفصيلية يدويًا حسب احتياجك (مثلاً: مستخدم يشوف "الإجمالي النهائي"
  بس من غير "إدارة المستخدمين").
- اضغط "حفظ / تعديل المستخدم".
- الصلاحيات بتتفعّل فورًا في السيرفر حتى لو المستخدم مسجل دخول بالفعل من قبل
  (بيتم التحقق من الصلاحية الحيّة من الشيت مع كل طلب).

## 6) نقاط أمان يفضل الانتباه لها مستقبلًا

- الرابط `API_URL` ظاهر في كود الواجهة (لازم يكون كده لأنه Frontend عام) — الحماية
  الحقيقية بقت في التحقق من الجلسة والصلاحية جوه السيرفر نفسه، مش في إخفاء الرابط.
- `Who has access: Anyone` على الـ Web App مطلوب عشان GitHub Pages تقدر تكلمه،
  وده طبيعي وآمن طالما التحقق من الجلسة شغال (زي ما هو متظبط دلوقتي).
- لو عدد اللجان/الأرقام كبر جدًا (آلاف الصفوف) وحسّيت إن الأداء بطّأ، الخطوة
  التالية المنطقية هي أرشفة البيانات القديمة في شيت منفصل، أو الانتقال لقاعدة
  بيانات حقيقية (Firebase/PostgreSQL) بدل Google Sheets — لكن الحجم الحالي المتوقع
  لأمانة/عدة أقسام Sheets هيبقى كفاية.
